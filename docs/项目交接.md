## 1. 项目做什么

这是一套 **HR 招聘到员工档案** 的后端，没有前端。调用方用 Header `x-token` 调 REST。

两条主链路不要混：

```text
候选人招聘（recordUuid）
  创建招聘记录 → 简历 → 复试 → 录用通知 → 办理入职（创建 user）
                                         ↘ 淘汰 / 放弃入职 → 人才库

正式员工入职登记（employeeUuid）
  办理入职后员工登录填表 → 提交 → HR 人员分配确认 → 进入档案

兼职员工
  HR 直接登记（创建 user + 已确认档案）→ 进入档案
```

| 阶段 | 业务主键 | 谁在用 |
| --- | --- | --- |
| 招聘候选人 | `recordUuid` | HR 管流程 |
| 员工主档 | `employeeUuid` | 员工填表；HR 审核/看档案 |
| 登录账号 | `user.id` / `user.username` | 全系统鉴权 |

`recordUuid` 和 `employeeUuid` 不是同一个东西。招聘流程结束后，`employee` 通过 `record_uuid` 或 `user_id` 挂回招聘记录和登录账号。

## 3. 鉴权、角色、错误码

### 3.1 Token

除 `/sso/login`、`/sso/register` 外，全部接口都要：

```http
x-token: <登录返回的字符串>
```

实现：`TokenInterceptor` 用 AES 解密 token（格式 `userId:issuedAt`），校验有效期（默认 1800 秒），再对 Redis key `user:{id}` 做会话校验。通过后把 `user.id` 写进 request attribute。**Controller / Service 只能从这里取操作人，请求体里的 `operatorUserId`、`createdBy`、`password` 一类字段一律当非法。**

登录成功响应体就是 token 字符串，不是 JSON 对象。

### 3.2 角色

`user.role`：`USER` / `HR` / `ADMIN`。客户端不能改角色。

| 角色 | 能做什么 |
| --- | --- |
| USER | 登录、改自己资料/密码、填自己的入职登记表 |
| HR / ADMIN | 招聘、岗位、人员分配、兼职登记、员工档案 |

招聘流程里的简历 / 复试 / 录用通知 / 淘汰 / 办理入职：当前实现 **只校验已登录**，没有再卡 HR。岗位、公司选项、招聘记录 CRUD、人员分配、兼职、档案才在 Service 层 `requireHrOrAdmin`。普通用户打这些管理接口返回 `403`。

### 3.3 统一错误

失败响应是 `ErrorResponse`，不是业务包装：

```json
{
  "timestamp": "2026-09-15T11:00:00",
  "status": 400,
  "error": "Bad Request",
  "message": "参数验证失败",
  "details": {}
}
```

| HTTP | 含义 |
| --- | --- |
| 400 | 参数、UUID、禁止字段、金额非法 |
| 401 | 未登录 / token 无效 / 会话过期 |
| 403 | 角色不够 |
| 404 | 记录不存在，或档案尚未 HR 确认 |
| 409 | 重复操作、唯一约束、已有值不可再改 |
| 422 | 状态机不允许（招聘流转、稼动非法转换、岗位终态） |

成功一般直接返回 VO / 数组 / `PageResult`，没有 `{ code, data }` 外壳。部分删除返回 `204`。

分页结构：

```json
{ "page": 1, "pageSize": 20, "total": 0, "totalPages": 0, "records": [] }
```

默认 `page=1`，`pageSize=20`，上限 100。

## 7. 岗位与公司（HR/ADMIN）

岗位状态和公司配额状态是两套：都用 `OPEN` / `CLOSED` / `COMPLETED`，但改配额 **不会** 改岗位整体状态。岗位软删除（`is_deleted=1`），审计保留。`COMPLETED` 是终态，不能再回到 `OPEN`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/recruitment-companies/options` | 未删除且 `ACTIVE` 的公司，给配额下拉用 |
| POST | `/api/recruitment-jobs` | 创建。服务端强制 `status=OPEN`，清洗职责 HTML |
| GET | `/api/recruitment-jobs/page` | 分页。`page`、`pageSize`、`jobName`、`status` |
| GET | `/api/recruitment-jobs/{jobUuid}` | 详情。已软删除 `404` |
| PUT | `/api/recruitment-jobs/{jobUuid}` | 只改业务字段，不能改状态/删除标记/版本/操作人 |
| PATCH | `/api/recruitment-jobs/{jobUuid}/status` | `{ "toStatus": "CLOSED", "remark": "暂停" }` |
| DELETE | `/api/recruitment-jobs/{jobUuid}` | 软删除，`204` |
| PATCH | `/api/recruitment-jobs/{jobUuid}/companies/{allocationUuid}/status` | 只改配额状态 |

创建岗位：

```json
{
  "jobName": "Java 开发",
  "jobCode": "JAVA-01",
  "jobDescription": "<p>后端开发</p>",
  "recruitmentRequirements": "3 年经验",
  "salaryMin": 10000,
  "salaryMax": 18000,
  "workLocation": "上海"
}
```

`OPEN <-> CLOSED` 允许；目标状态与当前相同 `409`；非法流转 `422`。

## 8. 招聘记录（HR/ADMIN）

前缀 `/api/recruitment-info`。创建时服务端生成 `recordUuid`、`id`、初始状态 `PENDING_INITIAL`。客户端不能写状态、操作人。

招聘类型：`INTERNAL`（默认）/ `OUTSOURCED`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/recruitment-info` | 创建，`201` |
| GET | `/api/recruitment-info` | 条件列表：`applicantName`、`position`、`status` |
| GET | `/api/recruitment-info/page` | 分页筛选 |
| GET | `/api/recruitment-info/statistics` | `pendingInitial` / `pendingRetest` / `pendingOnboarding` / `notPassed` |
| GET | `/api/recruitment-info/{recordUuid}` | 按业务 UUID |
| GET | `/api/recruitment-info/by-id/{id}` | 按自增编号 |
| PUT | `/api/recruitment-info/{recordUuid}` | 改资料，不能改状态 |
| POST | `/api/recruitment-info/{recordUuid}/status` | 状态动作（见下） |
| GET | `/api/recruitment-info/{recordUuid}/status-history` | 未包装 JSON 数组，按 `id ASC` |
| DELETE | `/api/recruitment-info/{recordUuid}` | 无历史 `204`；已有历史 `409` 且记录保留 |

创建示例：

```json
{
  "applicantName": "李四",
  "gender": "男",
  "position": "Java 开发",
  "jobUuid": null,
  "phone": "13912345678",
  "email": "lisi@example.com",
  "applicationChannel": "Boss",
  "recruitmentType": "INTERNAL",
  "initialContactPerson": "王HR"
}
```

分页还可带：`phoneOrEmailKeyword`、`initialContactPerson`、`retestContactPerson`、`applicationChannel`、`createdFrom`、`createdTo`。

### 状态机

```text
PENDING_INITIAL → RETEST_REVIEW → PENDING_RETEST → PENDING_ONBOARDING → ONBOARDED
任意活动态 → REJECTED / DECLINED
```

终态：`ONBOARDED`、`REJECTED`、`DECLINED`。

动作（请求只传 `action`，不传目标状态）：

| action | 从 | 到 |
| --- | --- | --- |
| `SUBMIT_RETEST_REVIEW` | PENDING_INITIAL | RETEST_REVIEW |
| `CONFIRM_RETEST` | RETEST_REVIEW | PENDING_RETEST |
| `COMPLETE_RETEST` | PENDING_RETEST | PENDING_ONBOARDING |
| `COMPLETE_ONBOARDING` | PENDING_ONBOARDING | ONBOARDED |
| `REJECT` | 任一活动态 | REJECTED |
| `DECLINE` | 任一活动态 | DECLINED |

```json
{ "action": "SUBMIT_RETEST_REVIEW", "remark": "初试通过" }
```

合法 `200`，非法 `422`。状态更新和历史写入同一事务。日常请走下面的复试 / 录用 / 入职 / 淘汰专用接口，它们会自己推进状态；不要跳过业务校验直接打 status。

### 录用通知 `/api/offers`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/offers/draft` | 草稿 `DRAFT`，`201`。同一招聘记录只能一份 |


### 淘汰与人才库 `/api/rejections`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/rejections/reject` | 活动态 → `REJECTED`，`201` |
| POST | `/api/rejections/decline` | 仅 `PENDING_ONBOARDING` → `DECLINED`。阶段/原因由服务端固定为 `ONBOARDING` / `CANDIDATE_DECLINED` |
| GET | `/api/rejections/talent-pool` | 可选 `talentCategory`、`rejectionReason`、`rejectionStage` |

淘汰：

```json
{
  "recordUuid": "{{recordUuid}}",
  "rejectionStage": "RETEST",
  "rejectionReason": "SKILL_MISMATCH",
  "talentCategory": "FUTURE_CONSIDER",
  "remark": "技能不匹配",
  "resumeAttachmentId": null
}
```

枚举：

- 阶段：`INITIAL_INTERVIEW` / `RETEST` / `BACKGROUND_CHECK` / `ONBOARDING`
- 原因：`SKILL_MISMATCH` / `CULTURE_MISMATCH` / `SALARY_EXPECTATION` / `OTHER` / `CANDIDATE_DECLINED`
- 人才库：`FUTURE_CONSIDER` / `SKILL_BACKUP` / `NOT_SUITABLE`

关联简历必须属于该招聘记录。终态 `422`，重复处理 `409`。

### 办理入职 `/api/onboarding`

把候选人变成可登录的 `user`，**还没有** HR 确认的员工档案。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/onboarding/process` | 仅 `PENDING_ONBOARDING`，`201`。用手机号当 `username` 建号 |
| GET | `/api/onboarding/{recordUuid}` | 入职记录。`initialPassword` 永远为 `null` |

```json
{
  "recordUuid": "{{recordUuid}}",
  "onboardingDate": "2026-09-15",
  "onboardingNote": "正式入职"
}
```

`initialPassword` **只出现在本次 201 响应**，必须安全交给候选人。密码是 BCrypt 入库，入职表无密码列。手机号已占用或已办理 `409`，状态不对 `422`，手机号空 `400`。

## 11. 入职登记（员工本人）

前缀 `/api/employee-onboarding`。登录员工填自己的表。`GET /me` 若还没有主档会建一份 `DRAFT`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-onboarding/me` | 当前草稿/已提交表，含 `progress` |
| PUT | `/api/employee-onboarding/me` | 存草稿 |
| POST | `/api/employee-onboarding/me/submit` | 校验必填步后提交 |
| POST | `/api/employee-onboarding/me/photo` | `multipart` 字段 `file`，`201` |
| GET | `/api/employee-onboarding/me/photo` | 一寸照，inline |

表单状态：`DRAFT` / `SUBMITTED`。已提交后再改会按实现拒绝或保持提交态，不要当成可反复提交。

提交必填步（`OnboardingStep`）：

| 步骤 | 必填 | 怎样算完成 |
| --- | --- | --- |
| BASIC_INFO | 是 | 姓名、性别、生日、手机、身份证、现住地址 |
| ACCOUNT_BIND | 是 | 微信号或已有 OpenID |
| FAMILY | 是 | 至少一条：姓名 + 关系 |
| EMERGENCY | 是 | 至少一条：姓名 + 电话 |
| PHOTO | 是 | 已上传一寸照 |
| EDUCATION | 是 | 至少一条完整学历 |
| TRAINING / WORK_HISTORY | 否 | |
| ID_DOCUMENT / EDU_CERTIFICATE | 否 | 本轮没有证件上传接口，进度里恒为未完成 |

请求体 `EmployeeOnboardingSaveRequest` 主字段 + 子表。子表最多各 20 条。不要传 `formStatus`、`employeeUuid`、`userId`。

```json
  "fullName": "张三",
  "gender": "男",
  "birthDate": "1998-01-01",
  "phone": "13912345678",
  "idCard": "110101199801011234",
  "currentAddress": "上海市浦东新区",
  "wechatAccount": "zhangsanwx",
  "educations": [
    { "sortNo": 1, "schoolName": "某大学", "major": "计算机", "educationLevel": "本科", "startDate": "2016-09-01", "endDate": "2020-06-30" }
  ],
  "familyMembers": [
    { "sortNo": 1, "fullName": "张父", "relationship": "父亲" }
  ],
  "emergencyContacts": [
    { "sortNo": 1, "fullName": "张父", "relationship": "父亲", "phone": "13800001111" }
  ],
  "workHistories": [],
  "trainings": []
}
```

子表字段：

- 学历：`sortNo`、`startDate`、`endDate`、`schoolName`、`major`、`educationLevel`、`certificate`
- 工作：`companyName`、`position`、`leaveReason`、`referenceName`、`referencePhone`
- 培训：`institution`、`courseContent`、`trainingResult`
- 家庭：`fullName`、`relationship`、`workUnit`、`jobTitle`（无电话）
- 紧急联络：`fullName`、`relationship`、`address`、`postalCode`、`phone`

用工类型 `FULL_TIME`。提交后进入人员分配待审核，**还不会**出现在档案列表。

## 12. 人员分配（HR/ADMIN）

前缀 `/api/employee-assignments`。只处理 **正式员工、已提交、尚未 `hr_confirmed`**。兼职打这些接口 `422`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-assignments` | 待审核列表 |
| GET | `/api/employee-assignments/{employeeUuid}` | 登记表详情 |
| GET | `/api/employee-assignments/{employeeUuid}/photo` | 一寸照 |
| POST | `/api/employee-assignments/{employeeUuid}/confirm` | 确认入职，写 `hr_confirmed_at` |

确认成功示例字段：`employeeUuid`、`fullName`、`message`（`{姓名} 入职成功`）、`hrConfirmedAt`。重复确认 `409`，未提交 `422`。

确认之后这条人才进入 `/api/employee-archives*`。

## 13. 兼职登记（HR/ADMIN）

前缀 `/api/part-time-employees`。没有「项目经理」角色。创建即已确认，**不走人员分配**。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/part-time-employees` | 创建账号 + 档案，`201` |
| GET | `/api/part-time-employees/{employeeUuid}` | 详情 |
| POST | `/api/part-time-employees/{employeeUuid}/photo` | 上传一寸照 |
| GET | `/api/part-time-employees/{employeeUuid}/photo` | 下载 |

请求体与入职登记相同，但姓名、手机必填。兼职创建时 **跳过一寸照必填**（可随后补传）。用手机号建 `user`，`employmentType=PART_TIME`，`employmentStatus` 默认 `REGULAR`，`hr_confirmed_at` 当场写入。

`201` 响应含 `username`、`initialPassword`、`employee`。初始密码只出现这一次。手机号已有账号 `409`。

## 14. 员工档案（HR/ADMIN）

前缀 `/api/employee-archives`。只返回 `hr_confirmed_at IS NOT NULL` 的人。未确认或 UUID 不存在一律 `404`。USER 访问 `403`。

**不要**和人员分配接口合成一套。档案里没有员工本人 Tab。

在职状态：`PROBATION` / `REGULAR` / `RESIGNED`。本轮 **没有** 转正、离职审批接口。工作地点：`HEADQUARTERS` / `DISPATCHED`。地点和客户名只能由稼动事件回写。

### 14.1 列表、统计、有限 PATCH

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-archives/page` | 已确认档案分页 |
| GET | `/api/employee-archives/statistics` | 五张全局卡，**不接受**筛选 |
| PATCH | `/api/employee-archives/{employeeUuid}` | 只改白名单字段 |

列表筛选（空条件不加 WHERE）：

- `fullName` / `phone` / `customerName` / `position`：前缀匹配
- `employmentStatus`：精确等于
- `page` / `pageSize`

列表项含：`employeeUuid`、`fullName`、`employeeNo`、`gender`、`phone`、`employmentStatus`、`hiredAt`、`regularizedAt`、`position`、`customerName`、`contractSalary`、`probationSalary`、`employmentType`。

统计卡（**不是互斥集合**，兼职计入所有适用项）：

- `probationCount` 试用
- `activeCount` 在职（试用 + 正式）
- `headquartersCount` 在职且总部
- `dispatchedCount` 在职且外派
- `resignedCount` 离职

PATCH 只允许：`department`、`companyEmail`、`probationEndDate`、`contractSalary`、`probationSalary`；`hiredAt` **仅当前值为空时**可补录，已有值再改 `409`。

```json
{
  "department": "研发部",
  "companyEmail": "zhangsan@company.com",
  "probationEndDate": "2026-12-15",
  "contractSalary": 15000,
  "probationSalary": 12000
}
```

请求里出现 `employmentStatus`、`workLocation`、`customerName`、`regularizedAt`、`password` 等任意未知字段 → `400`。

### 14.2 个人信息

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-archives/{employeeUuid}` | 头图 + 登记子表，只读，**无** `progress`，**无** 照片路径 |
| GET | `/api/employee-archives/{employeeUuid}/photo` | 一寸照 |

头图计算字段不落库：

- `age`
- `tenureMonths` 工龄月数
- `probationRemainingDays`：非试用或无预计转正日为 `null`，已过期为 `0`
- `hrSystemAccount` = `user.username`

### 14.3 月度薪资

天数是 HR 手工可空快照，**不接考勤、不进公式、不表示申请流水**。本接口不返回加班/调休/请假/出差列表。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-archives/{employeeUuid}/salaries` | 按月倒序 |
| POST | `/api/employee-archives/{employeeUuid}/salaries` | 登记一个月，`201` |

列表额外字段：`salaryTotal`（实发合计）、`overtimePayTotal`、`recordCount`、`dayCountsAreManualSnapshots=true`、`attendanceFlowsExcluded=true`。

服务端计算并落库：

```text
gross_pay = base_salary + position_allowance + overtime_pay + bonus + subsidy + other_pay
net_pay   = gross_pay - social_insurance - housing_fund - tax_amount
```

```json
{
  "salaryMonth": "2026-09-01",
  "department": "研发部",
  "scheduledDays": 22,
  "actualDays": 21,
  "leaveDays": 1,
  "baseSalary": 10000,
  "positionAllowance": 2000,
  "overtimePay": 500,
  "bonus": 0,
  "subsidy": 200,
  "otherPay": 0,
  "socialInsurance": 800,
  "housingFund": 500,
  "taxAmount": 300,
  "taxRate": 3,
  "remark": "试用期"
}
```

`salaryMonth` 必填（存该月 1 号）。金额缺省当 0。带 `grossPay` / `netPay` / `salaryUuid` / `createdBy` → `400`。同月重复 `409`。负金额或实发为负 `400`。三个天数可省略；填了必须是 `>= 0` 的整数。

### 14.4 稼动事件

这是 **事件日志**，不是时间段表。`ENTER` 结束日 = 其后第一条 `RETURN.event_date`，没有则进行中。时长文案服务端格式化。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-archives/{employeeUuid}/assignments` | 履历 + 汇总 |
| POST | `/api/employee-archives/{employeeUuid}/assignments` | 追加事件，`201` |

汇总：`projectCount` = `ENTER` 条数；`inProgressCount`；`accumulatedDurationText`（进行中也计入）。

写入顺序：先 `SELECT ... FOR UPDATE` 主档 → 插事件 → 同一事务回写 `work_location` / `customer_name`。

规则：

- `ENTER`：当前必须是总部，且必须有 `companyName` → 主档变为外派，客户名 = 公司名
- `RETURN`：当前必须是外派，**禁止**带客户 → 主档回到总部，客户名清空
- 非法转换 `422`，零行写入，主档不变
- 事件日期早于最后一条 `400`

```json
{ "assignmentType": "ENTER", "eventDate": "2026-09-01", "companyName": "客户A", "utilizationRate": 100, "remark": "进场" }
```

```json
{ "assignmentType": "RETURN", "eventDate": "2026-10-01", "remark": "归任" }
```

### 14.5 系统账号

不存密码。响应无 `password`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/employee-archives/{employeeUuid}/accounts` | 第一条固定只读「人力资源系统」=`user.username`，后面是手录行 |
| POST | `/api/employee-archives/{employeeUuid}/accounts` | 手录一行，`201` |

```json
{ "systemName": "OA", "accountName": "zhangsan", "openedAt": "2026-09-15T09:00:00" }
```

带 `password` / `accountUuid` / `operatorUserId` → `400`。

## 15. 推荐联调顺序

1. `POST /sso/login` 拿 HR token。
2. （可选）创建岗位，拿 `jobUuid`。
3. `POST /api/recruitment-info` 拿 `recordUuid`。
4. 上传简历 → 申请复试 → 确认复试 → 录用草稿 → 发送 → `PENDING_ONBOARDING`。
5. `POST /api/onboarding/process`，保存一次性密码；用候选人手机号登录。
6. 员工 token 调 `/api/employee-onboarding/me*` 填表、传照片、提交。
7. HR token 调 `/api/employee-assignments` 确认。
8. HR 再调 `/api/employee-archives*` 维护薪资、稼动、账号。

兼职：HR 直接 `POST /api/part-time-employees`，跳过 4–7。

端到端自动化参考：`src/test/java/com/example/study11/recruitment/integration/Session30EndToEndTest.java`。

## 16. 写代码时不要破坏的约束

- 操作人、角色、状态、软删除、版本号由后端维护。
- 禁止字段出现在 JSON 里就 `400`，不要静默忽略。
- 薪资应发/实发只在服务端算；天数不进公式。
- 主档 `work_location` / `customer_name` 只能由稼动事件在同一事务更新。
- 兼职默认 `REGULAR`；正式员工无状态时回填 `PROBATION`。
- 失败事务不能留下半条数据（稼动非法转换、重复月份薪资都已按此测过）。
- 密码、初始密码、token、一寸照/简历磁盘路径不要写进日志或响应（办理入职/兼职创建的一次性密码除外）。
- 招聘 `recordUuid` 流程和员工 `employeeUuid` 档案不要合成一套 Controller。
